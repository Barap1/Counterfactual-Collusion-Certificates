## What it is

Branching runs over the **real upstream objects**: `JiraTicketEnvironment`, `CollusionPrompts`, `LocalCommunicationProtocol`, `Megaboard`, `BaseAgent` with its multi-step tool loop, and `TogetherClient`'s message/tool bookkeeping. Only run.py's setup and turn loop are re-implemented, and that re-implementation is checked against the archived pilot. A scripted deterministic LLM replaces the provider.

- **Strategy A (primary): explicit snapshot.** The source run stores immutable, content-addressed dynamic snapshots at every turn boundary. A branch rebuilds the static world from the spec, verifies its static hash, and loads the snapshot from bytes, so it shares no containers with anything else.
- **Strategy B (cross-check): prefix reconstruction.** Rebuilds from turn 0 using recorded responses. Each request is hash- and order-checked. The result must equal the snapshot byte-for-byte.
- **Arms:**
  - **F:** upstream render, no hook.
  - **S:** identity hook through the intervention path.
  - **K:** pure receiver-only removal of the declared event ids, over a `persistent` or `single` horizon.
- **Freshness:** every post-fork call is a new client call (`cache_mode=fresh`, unique response ids). Nothing recorded after the boundary is ever fed to a branch.

## Exact vs approximate

**Exact (byte-level, deterministic fixture):**
- Restore is exact.
- Prefix reconstruction equals the snapshot.
- F, S and the source deliver byte-identical receiver requests at t*.
- With identical content, F and S reach identical final state.
- K's prompt equals F's prompt minus exactly the masked lines (plus renumbering), at t* and at every prompt in the horizon.
- Non-receivers are unchanged.
- Pilot parity: archived blackboards (excluding id/ts) and final rewards are reproduced exactly from archived tool events.

**Approximate or declared:**
- Event ids and ts come from a logical clock instead of uuid4 and wall time.
- Leak detection is a heuristic (exact substring / 8-shingle ≥0.5 / raw id); paraphrase goes undetected.
- `log_prompts=False` (file side effect only).
- With a real provider, F and S are equal only in distribution. Provider RNG, cache and routing are inaccessible, so byte identity holds only up to the first sampled token.

## Fixture interface (for FIX-001)

`ccc.replay.fixtures.ReplayFixture(name, spec: WorldSpec, policy_factory: () -> Policy, select_exposure: SourceRun -> ExposureSpec, expect)` is run by `run_fixture(fx)`.

- A `Policy` maps `PolicyCall` (agent, phase, messages, tool_names) to `{"content", "tool_calls": [{"name", "arguments"}]}`. It is wrapped as `ScriptedClient(policy, nonce=...)`. FIX-001's `ccc/fixtures/replay_adapter.py` already targets this signature.
- Lower-level entry points: `record_source_run`, `candidate_exposures`, `make_checkpoint(strategy=...)`, `run_branch(arm, hook=...)`, `audit`.
- Built-in example: `signal_fixture()`.

## Limitations

- Jira/collusion path only.
- Single-world, single-process prototype. No branch ledger on disk yet and no INF-001 controller client.
- Only event-level masking of blackboard events. The C (channel) and R (repair) arms are not implemented, though a custom `hook=` supports them.
- Leak detection is heuristic.
