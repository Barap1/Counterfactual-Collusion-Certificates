## Key findings

- Agents have **no cross-turn memory**. `BaseAgent` builds a fresh `[system, user]` context every turn (`terrarium/agents/base.py:335`). The only persistent surfaces are the blackboards, which are fully re-rendered every turn (`local_protocol.py:117`, `blackboard.py:442`), plus `CURRENT ASSIGNMENTS` and the private state.
- There is no mid-turn read path: `get_blackboard_events` is neither advertised nor routable. A turn boundary is therefore an exact pre-exposure checkpoint.
- **Hooks.**
  - (a) Checkpoint at the boundary before the receiver's first turn whose prefetch contains the event.
  - (b) Receiver mask: a pure view hook in a `LocalCommunicationProtocol._prefetch_blackboard_events` override, rendered by the upstream formatter.
  - (c) Sham: the same path with the identity transform. F uses the untouched upstream method.
  - Recorder: wrapper around each agent's client (`generate_response`).
- **Inaccessible state:**
  - Provider-side sampling, caches, routing and model aliasing.
  - `TogetherClient` forwards only model/messages/max_tokens/temperature/reasoning/tools, so no seed can be claimed.
  - The global `random` is used only for retry jitter.
  - Wall-clock ts and uuid4 event ids are replaced by a logical clock; the ids are rendered into prompts for `action_executed` lines.
- **Hazards:**
  1. `providers.py:107` monkeypatch → `resolve_model` loads `compute.env`, honours `LLM_MODEL`, and fetches the OpenRouter catalog during env construction. 136 blocked connects were observed offline; CCC scopes a pure replacement. *Hypothesis:* this explains the pilot model mismatch.
  2. The secret board is never scrubbed of `action_executed` traces (no template).
  3. Shallow-copy aliasing of tool results into board events.
  4. Upstream swallows continuation-step exceptions.
  5. `PromptLogger` writes `./logs` in the cwd, and `clear_seed_directories` runs `rmtree`.
  6. The mask renumbers later `[i]` lines.
